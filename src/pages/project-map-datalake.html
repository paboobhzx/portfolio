01 // The Architecture

The pipeline is entirely serverless. Raw data files (CSV, JSON, Parquet) are dropped into a raw S3 bucket. An S3 event triggers a Python Lambda that validates and routes the file. AWS Glue crawls the processed bucket, updates the Data Catalog, and runs ETL jobs to transform and partition the data. Athena queries the processed layer with SQL on demand.

02 // The Schema Evolution Challenge

Raw data sources rarely deliver clean, consistent schemas. Files arrive with missing columns, changed types, or new fields that break downstream Glue jobs. The pipeline needs to handle schema drift gracefully — detecting changes, updating the Glue Catalog, and not dropping data mid-pipeline when source schemas evolve.

terminal Engineering Insight

"The pipeline's job isn't just to move data — it's to guarantee that the data arriving at Athena is always in a known, queryable shape, regardless of what the source throws at you."

03 // Key Engineering Decisions

Ingestion Pattern

S3 Event → Lambda (no scheduler)

Files trigger the pipeline the moment they land in S3 — no cron jobs, no polling. Lambda runs only when there's work. This eliminates idle compute cost and makes latency between arrival and processing near-zero, while keeping the architecture entirely event-driven.

Transformation

AWS Glue for ETL

AWS Glue handles schema inference, cataloging, and PySpark-based transformations. The Glue Crawler keeps the Data Catalog updated when source schemas evolve. Glue jobs partition the output by date, making Athena queries efficient without full table scans.

Query Layer

Athena — SQL on S3

Athena makes the processed data queryable with standard SQL directly on S3 — no cluster to provision, no indexes to maintain, no database server running 24/7. Pay only per query scanned. For a data lake with infrequent ad-hoc queries, this is the right economics.

Automation

GitHub Actions + Terraform CI/CD

Every infrastructure change goes through a GitHub Actions workflow: Terraform plan runs on PR, apply runs on merge to main. No manual console changes. Every infrastructure change is code-reviewed, version-controlled, and auditable in git history.
