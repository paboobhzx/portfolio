StarMan:
Polyglot
Microservices Platform.

A multi-language microservices e-commerce platform. Cart and Order services in C# .NET 8, Inventory in Java Spring Boot 3, a React frontend, all running on Docker and deployed to AWS with Terraform.

01 // The Architecture

StarMan is a polyglot microservices platform — each service is written in the language best suited to its domain, each runs in its own Docker container, and each has its own database. The React frontend talks to services via an API Gateway. Everything is deployed on AWS ECS Fargate with Terraform-managed infrastructure.

02 // The Polyglot Challenge

Running multiple services in different languages on the same platform forces you to solve cross-cutting concerns — logging, error propagation, API contract consistency — without shared libraries. Each service team (even if it's one person) must treat the other services as external dependencies with documented contracts.

terminal Engineering Insight

"Polyglot microservices isn't about using every language — it's about using the right language for each domain, and owning the cost of that decision at the contract boundary."

03 // Key Engineering Decisions

Language Strategy

C# for Transactional, Java for Inventory

C# .NET 8 handles Cart and Order — services with complex transactional logic where strong typing and the .NET ecosystem (Entity Framework, LINQ) shine. Java Spring Boot 3 handles Inventory — a domain with heavier query complexity where JPA and Spring Data offer proven patterns.

Containerization

One Container per Service

Each service ships as its own Docker image. This enforces isolation at the build level — no shared dependencies, no version conflicts between runtimes. ECS Fargate runs each container independently, and services can be scaled, updated, or replaced without touching the others.

Data Isolation

Per-Service Persistence

Each microservice owns its own database. No shared schema, no joins across service boundaries. Services communicate via API calls — not foreign keys. This makes each service independently deployable and prevents data coupling from sneaking back in through the database layer.

Deployment

ECS Fargate + Terraform

AWS ECS Fargate runs the containers without managing EC2 instances. Terraform provisions the full stack: VPC, subnets, security groups, ECS cluster, task definitions, ALB, RDS instances, and IAM roles. A single terraform apply brings the platform from zero to production.
