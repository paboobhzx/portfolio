Project Context + Objective

SuperZAP centralizes WhatsApp operations for support and sales teams: operator assignment with role-based access (agent/manager), conversation queue management, contact CRM with origin tracking and attempt history, dynamic scripts for guided responses, and real-time supervisor visibility over live conversations.

Architecture Overview

  • Node.js + Express backend with 19 domain-scoped controllers and repositories.
  • Socket.IO for real-time message delivery, typing indicators, and operator status sync.
  • MySQL (RDS) with 14+ tables, tenant-scoped isolation, and 50+ indexes.
  • Evolution API (Dockerized) for WhatsApp protocol integration with circuit breaker and webhook ingestion.
  • Terraform-managed AWS stack: VPC, EC2, RDS, S3, CloudFront, SSM, and IAM roles.
  • Cloudflare Tunnel for HTTPS exposure without Elastic IP or NAT Gateway.

End-to-End Flow

  • WhatsApp events arrive via Evolution API webhook (rate-limited at 300/min per IP).
  • Backend resolves tenant/instance, persists message, and updates conversation state.
  • Socket.IO broadcasts to tenant-scoped rooms for instant UI updates.
  • Operators compose replies through chat UI; messages route through Evolution API back to WhatsApp.
  • Media files upload to S3 with presigned URLs; fallback fetches from Evolution if S3 path is missing.
  • CRM drawer aggregates unified history: messages, contact attempts, internal notes, and origin changes.

Stack + Key Services

React 19 (TypeScript/Vite) frontend, Node.js 20 + Express backend, MySQL2 connection pool, Socket.IO 4.8 for realtime, Evolution API (Docker) for WhatsApp, S3 for media storage, CloudFront CDN, Argon2 password hashing, custom JWT auth (HMAC-SHA256), PM2 process supervision, and Terraform modules for VPC/RDS/EC2/S3/CloudFront/SSM.

Delivery Metrics / Scale Indicators

  • 20 route modules exposing 80+ HTTP endpoints across auth, conversations, messages, operators, scripts, origins, attempts, leads, broadcasts, and diagnostics.
  • 19 controllers + 19 repositories following strict domain separation.
  • 26 chat UI components (ConversationList, MessageBubble, ContactPanel, CRM sections) plus 9 admin components.
  • 8 data hooks (useConversations, useMessages, useOperators, usePipeline) orchestrating real-time state.
  • Infra: EC2 (t3.medium), RDS MySQL 8.0, 2 S3 buckets, VPC with public + private subnets, SSM Parameter Store for secrets.

Engineering Decisions + Tradeoffs

  • Custom JWT over AWS Cognito reduces external dependencies; operator sessions stored in DB enable lockout and expiry enforcement.
  • Single-node Socket.IO simplifies deployment but limits horizontal scaling (Redis adapter needed for multi-EC2).
  • Tenant-scoped DB queries enforce data isolation at application level rather than row-level security, trading enforceability for flexibility.
  • S3 media with Evolution fallback ensures backward compatibility during migration from direct API storage.
  • Webhook rate limiting + circuit breaker on Evolution API protects against bursts without message loss.
