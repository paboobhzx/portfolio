Project Context + Objective

SuperDoc was built to handle high-variance document workloads (conversion, extraction, transformation) with predictable throughput, explicit job state, and lifecycle-controlled storage.

Architecture Overview

  • Frontend application for upload, processing status, and download lifecycle.
  • API Gateway + Lambda handlers for presign, job management, billing hooks, and orchestration.
  • SQS dispatcher pipeline invoking capability-specific workers.
  • Modular Terraform infrastructure defining compute, queues, storage, auth, and delivery.

End-to-End Flow

  • Client requests upload URL and creates processing job metadata.
  • Uploaded asset is stored in S3 and queued for asynchronous execution.
  • Dispatcher routes work to PDF/DOCX/XLSX/media specialized handlers.
  • Worker writes outputs, updates job status, and publishes retrieval metadata.
  • User polls job endpoint and downloads outputs using presigned URLs.

Stack + Key Services

React frontend, API Gateway, Lambda (Python), SQS + DLQ, DynamoDB, S3 lifecycle buckets, EventBridge schedulers, CloudFront, Amplify, Cognito-protected admin routes, Terraform modules.

Delivery Metrics / Scale Indicators

  • Large handler surface with dedicated conversion paths for multiple formats.
  • Long-running worker profile supports heavier operations without blocking API ingress.
  • Queue and sweeper jobs provide backpressure control and retention hygiene.

Engineering Decisions + Tradeoffs

  • Specialized workers reduce blast radius per capability while increasing deployment/monitoring overhead.
  • Async queue-based execution improves throughput consistency and introduces eventual consistency for UX.
  • Lifecycle-managed storage controls cost, but requires clear expiration semantics for users.
