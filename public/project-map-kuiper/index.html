Project Context + Objective

Kuiper enables users to upload PDF documents, automatically extract and process text using OCR, index content into a vector knowledge base, and ask intelligent questions grounded in the uploaded documents. Built entirely serverless with 15 Terraform files managing the full AWS stack.

Architecture Overview

  • React frontend (Vite) deployed via S3 + CloudFront with Origin Access Control.
  • API Gateway HTTP API with 3 endpoints: /upload, /chat, /status.
  • Step Functions state machine orchestrates the 4-stage processing pipeline (upload, Textract OCR, text extraction, KB sync).
  • Bedrock Knowledge Base with Titan embeddings for vector search and Amazon Nova Pro for LLM responses.
  • DynamoDB ingestion-locks table prevents race conditions during concurrent uploads.
  • Custom domain (kuiper.pablobhz.cloud) with Route53, ACM certificates, and CloudFront CDN.

End-to-End Flow

  • User uploads PDF via frontend; upload handler validates, stores in raw-documents S3 bucket, and starts Step Functions execution.
  • State machine routes to Textract adapter Lambda, which calls detect_document_text() and stores JSON output in processed-documents bucket.
  • Extract-text Lambda parses Textract LINE blocks, joins text, and writes to processed-documents/text/.
  • EventBridge triggers ingestion handler on chunk creation; DynamoDB lock acquired, then Bedrock StartIngestionJob syncs to Knowledge Base.
  • Chat handler calls bedrock-agent-runtime.retrieve() for vector search (top 5 results), assembles context, and invokes Nova Pro (temperature 0.1, max 1000 tokens).
  • Response returned with debug info: KB ID, results count, context length, and relevance scores.

Stack + Key Services

React 18 (Vite) frontend, Python 3.11 Lambda functions, Step Functions (ASL JSON), AWS Textract for OCR, Bedrock Knowledge Base (Titan embeddings + S3 Vectors), Amazon Nova Pro LLM, API Gateway v2, 5 S3 buckets (frontend, raw-documents, processed-documents, kb-documents, pipeline-artifacts), DynamoDB, CloudFront with OAC, Route53, ACM, and 15 Terraform configuration files.

Delivery Metrics / Scale Indicators

  • 7 Lambda functions totaling 834 lines of Python: upload handler, Textract adapter, text extractor, KB sync, chat handler, status checker, and S3 cleanup.
  • 15 Terraform files (1,573 lines) managing 100+ AWS resources with IAM least-privilege roles per function.
  • 4-stage processing pipeline: Upload, OCR, Text Extraction, Knowledge Base Sync.
  • Dual AWS providers: primary for resources, us-east-1 alias for ACM certificates (CloudFront requirement).

Engineering Decisions + Tradeoffs

  • Fully serverless architecture eliminates baseline ops cost but requires disciplined observability across Lambda, Step Functions, and Bedrock.
  • DynamoDB lock table with TTL prevents race conditions during concurrent ingestion jobs, adding a coordination layer to the otherwise stateless pipeline.
  • Bedrock KB created manually (Terraform limitation) while all other 100+ resources are IaC-managed, creating a single manual dependency.
  • Multi-bucket S3 strategy isolates processing stages for independent scaling and audit trails, at the cost of more complex IAM policies.
  • CloudTrail-driven IAM debugging resolved service role trust issues for Bedrock KB, documented as enterprise-grade troubleshooting reference.
